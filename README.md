# Demon Bluff 标准模式决策助手

Windows 本地公平游玩伴侣。程序只读取玩家可见的截图和确认后的信息，使用本地 OCR、版本化角色目录与 Z3 约束求解器判断恶徒，再由可选的 DeepSeek、OpenAI 或其他兼容模型解释下一步策略。它不读取 `Player.log` 中的隐藏真身、不修改游戏内存，也不自动点击游戏。

## 识别与推理方案

默认流程不需要视觉模型，也不会为截图消耗 API 额度：

1. `Ctrl+Shift+D` 只截取前台 `Demon Bluff.exe` 的客户区。
2. 内置 RapidOCR/ONNX 在本机识别简中和英文文字。
3. 程序用有限的角色名称词典、模糊纠错和卡牌几何锚点，把角色、牌号、统计数量与状态配对。
4. 低置信结果进入“待确认”区；玩家确认或修正前，不会写入局面，也不会发给模型。
5. 本地 Z3 枚举一致世界、检查冲突并计算合法动作。
6. 只有确认后的文字局面、相关角色规则和求解报告会交给 DeepSeek 等策略模型。

这套分工让 OCR 准确性依赖可重复测试的本地规则，而不是让 LLM 猜截图；LLM 也不能覆盖求解结论、虚构牌位或建议非法动作。

## 快速开始

### 直接运行 EXE

1. 双击 `dist\DemonBluffAssistant-v0.3.3.exe`。
2. 浏览器会打开 `http://127.0.0.1:8765`。
3. 在 Demon Bluff 位于前台时按 `Ctrl+Shift+D` 截取牌桌总览。
4. 返回伴侣页点击“识别并创建村庄”，检查本地 OCR 摘要后点击“确认创建”。
5. 后续截图使用“解析当前局面”，修正识别结果后点击“确认并分析”。
6. 需要 LLM 策略解释时，在页面顶部“模型与 API”中配置 DeepSeek；不配置也能使用本地求解和模板建议。

点击 Web 页面中的截图预览可打开大图查看器，并可在 50%～400% 范围缩放。恶魔和爪牙数量都允许为 0。

独占全屏模式不保证能正确截图，请使用窗口化或无边框模式。截图默认只保存在内存中。

如果助手没有正常退出，或启动时提示 8765 端口被占用，双击：

```text
dist\StopDemonBluffAssistant.exe
```

它只会结束 `DemonBluffAssistant.exe` 和 `DemonBluffAssistant-*.exe`，不会结束游戏本体，也不会误杀关闭工具自身。该工具可以长期复用。

### 从源码运行

需要 Windows 和 Python 3.12：

```powershell
.\setup.ps1
.\start.ps1
```

首次安装会创建 `.venv`，并下载本地 OCR 运行库和模型。打包版已包含模型，首次识别可能需要几秒初始化，之后无需联网。

## DeepSeek 与其他策略模型

模型功能完全可选。没有 API Key 时，截图识别、手工修正、本地 Z3 求解、冲突检查和模板建议仍可使用。

无需命令行配置：

1. 打开页面顶部“模型与 API”。
2. 选择 DeepSeek、OpenAI 或“其他 OpenAI-compatible”。
3. 选择或输入模型 ID，粘贴 API Key。
4. 点击“加密保存并切换”。

### DeepSeek

官方接口地址固定为 `https://api.deepseek.com`，页面内置：

- `deepseek-v4-pro`
- `deepseek-v4-flash`

DeepSeek 只负责确认后的文字策略推理。程序会给它发送精简的可见牌面、事件、相关角色规则、Z3 结论和合法动作；不会发送截图。API Key 直接在本地页面配置即可。

### OpenAI 与兼容提供商

OpenAI 也默认只用于文字策略。后端仍保留可选的 OpenAI 视觉解析接口，便于开发对照，但伴侣页的正常截图流程默认使用本地 OCR。

选择“其他 OpenAI-compatible”时填写模型 ID、Base URL 和 API Key。兼容提供商通过 `/chat/completions` 的 JSON 输出生成文字策略。公网 Base URL 必须使用 HTTPS；仅 `localhost`、`127.0.0.1` 和 `::1` 允许明文 HTTP。URL 不得内嵌凭据、查询参数或片段。

每个提供商的凭据独立保存。API Key 只发送到本机 `127.0.0.1` 后端，使用当前 Windows 用户的 DPAPI 加密后写入 `data/model-config.json`；浏览器、局面导出 JSON 和仓库都不保存明文。留空 Key 会保留已有凭据，勾选“删除”才会清除。

## 使用流程

1. 抓取包含牌数、恶徒/爪牙/恶魔数量的总览，自动识别并创建村庄。支持从 `#1…#N` 推导牌数，并理解“2个爪牙和0个恶魔”“杀死恶徒：0/2”这类实际界面文案。
2. 关键数量缺失时程序不会猜测，而会要求重新截图；生命值缺失时会临时填 10 并明确警告玩家确认。
3. 打开牌组或已翻开角色画面继续抓图，将角色和可见状态加入待确认区。
4. 修正牌号、角色、翻开/死亡/腐化状态和证词；需要核对时可直接导出当前识别结果 JSON，然后确认。
5. 查看一致世界数、恶徒分级、合法动作和建议。
6. 录错时撤销上一事件；局面可以随时导出或导入 JSON。

结论含义：

- **必恶 / 必善**：所有已枚举的一致世界都相同。
- **偏恶**：显示恶徒一致世界占比；这不是真实概率。
- **未定**：当前信息不足。
- **冲突**：录入信息无解，程序列出冲突事件并停止给出处决建议。

## 识别准确性与隐私

本地 OCR 使用三层校验：OCR 字符置信度、Demo 角色目录匹配、牌位空间关系。原始 OCR 文字会随待确认结果返回，方便定位漏字和误字。任何结果都必须由玩家确认后才进入求解器。

默认截图仅驻留在最多 5 张的内存队列中。只有显式设置下面的变量才会保存调试截图：

```powershell
$env:DEBUG_SAVE_SCREENSHOTS = "1"
```

保存位置为数据目录下的 `debug-screenshots`。

## 开发与构建

```powershell
.\.venv\Scripts\python.exe -m pytest
.\build.ps1 -Name DemonBluffAssistant-v0.3.3
```

构建产物：

- `dist\DemonBluffAssistant-v0.3.3.exe`
- `dist\StopDemonBluffAssistant.exe`

本地 API 只绑定 `127.0.0.1`，校验 Host 请求头，默认端口为 8765，可通过 `DEMON_BLUFF_PORT` 修改。截图响应禁止浏览器缓存。若端口被旧版占用，新版会显示明确提示而不会打开旧页面。

## 当前限制

- 仅覆盖当前 Demo 标准模式；无尽模式、遗物、牌组构筑和自动操作不在范围内。
- 游戏更新角色文本后，需要同步角色目录和规则测试。
- 小字号、动画模糊、遮挡或极低对比度会降低 OCR 准确率，应重新截取静止且清晰的画面。
- 当前已有合成图和解析单元测试，但尚未收集完整的简中/英文真实游戏金样，因此不能诚实宣称已达到 95% 实战识别率。达到该指标仍需用真实的 2560×1440、2560×1600 及窗口尺寸截图做回归校准。

## 发布到 GitHub

发布脚本不会保存 GitHub Token，也不会强制推送。它要求本机已经安装并登录 GitHub CLI，并在上传前拒绝包含 `data`、`dist`、`build`、`.venv` 或 `.env` 的目录。

```powershell
.\publish-to-github.ps1 -Visibility public
```

默认目标为 `BobbyEasy/DemonBluffAssistant`，也可以通过 `-Owner` 和 `-Repository` 参数覆盖。
